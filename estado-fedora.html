📌 Versão do Fedora

Verificação de compatibilidade

O FOF é desenvolvido e testado no Fedora 44. Se você está numa versão diferente, alguns comandos podem se comportar de forma inesperada (pacotes renomeados, repositórios alterados, sintaxe nova). Esta verificação avisa quando isso acontece.

ℹ️ Versões suportadas: Fedora 43, 44 e 45. Versões mais antigas (42 e anteriores) ou mais novas (46+) podem exigir ajustes manuais. O FOF continua funcionando, mas você pode precisar adaptar algum comando específico.
🧊 Fedora Atomic / Silverblue

Detecção de sistema imutável

O Fedora tem duas variantes: a "tradicional" (Workstation, KDE, etc) e a "imutável" (Silverblue, Kinoite, Bazzite, Bluefin). Nas variantes imutáveis, o sistema base é protegido e não pode ser modificado por dnf install — só por rpm-ostree ou bootc.

ℹ️ Por que isso importa: o FOF usa dnf para instalar a maioria dos pacotes. Se você está num sistema imutável, esses comandos vão falhar (ou pior, exigir override). Esta detecção avisa antes de você tentar algo que não vai funcionar.
🛡️ SELinux
O SELinux é o sistema de controle de acesso obrigatório do Fedora. Ele impõe regras rígidas sobre o que cada processo pode fazer — mesmo processos rodando como root são limitados. É o maior mistério do Fedora para quem vem de outras distribuições, e a causa mais comum de "por que isso não funciona?".

📊 Status Atual

Mostra o modo atual do SELinux (enforcing, permissive ou disabled).

ℹ️ Modos do SELinux:
  • Enforcing — regras ativas e bloqueios reais. É o padrão do Fedora e o recomendado.
  • Permissive — regras ativas mas apenas registra, não bloqueia. Bom para diagnosticar.
  • Disabled — regras desativadas. Não recomendado — reduz a segurança do sistema.

🔍 Avisos Recentes (AVC Denials)

Lista os avisos de "AVC denial" das últimas 24 horas. Cada AVC é uma tentativa de acesso que o SELinux bloqueou. Nem todo bloqueio é problema — muitos são ruído de processos que tentam acessar coisas fora da política, mas o padrão ajuda a identificar problemas reais.

ℹ️ Como interpretar: um AVC isolado geralmente é inofensivo. Vários AVCs repetidos do mesmo processo indicam que ele está tentando algo que o SELinux não permite — isso merece investigação.

🛠️ setroubleshoot — Assistente de Diagnóstico

Instala o setroubleshoot, um pacote oficial do Fedora que analisa automaticamente cada AVC e sugere uma correção — em linguagem clara, sem jargão de SELinux. É o que transforma "usuário_u:role_r:tipo_t" em "o Apache não consegue ler arquivos em /var/www/html, você deve rodar tal comando".

ℹ️ O que é instalado: setroubleshoot-server (motor de análise), setools-console (ferramentas CLI) e policycoreutils-python-utils (utilitários de política). Os avisos aparecem automaticamente no menu de notificações do desktop quando um AVC é gerado.

🖥️ Gerenciador SELinux (Interface Gráfica)

Instala o policycoreutils-gui, que fornece uma interface gráfica completa para gerenciar o SELinux: booleans, contextos de arquivo, mapeamento de portas, usuários, e outras configurações avançadas. É o jeito mais amigável de ver e ajustar o SELinux no Fedora.

ℹ️ O que dá para fazer com ele:
  • Ver e alternar booleans (chaves liga/desliga de funcionalidades)
  • Ver contextos de arquivo (o que cada pasta pode acessar)
  • Configurar portas permitidas para cada serviço
  • Gerenciar usuários SELinux
ℹ️ Sobre a senha: ao abrir o Gerenciador SELinux, ele vai pedir a senha de administrador — isso é normal. Sem root, ele só permite visualizar; para alterar, precisa de privilégio.

⚠️ Sobre desabilitar o SELinux

Muitos tutoriais na internet recomendam desabilitar o SELinux quando algo não funciona. Isso não é uma boa prática no Fedora — o sistema é projetado para funcionar com ele ativo, e desabilitar mascara problemas em vez de resolvê-los.

Antes de pensar em desabilitar, tente:
1. Instalar o setroubleshoot (botão acima) — ele explica cada aviso em português claro.
2. Verificar se existe uma política específica para o que você está tentando fazer (semanage).
3. Se for um caso específico, ajustar apenas o contexto do arquivo/pasta em questão (chcon).
4. Só como último recurso, mudar o SELinux para modo permissive (registra mas não bloqueia) — mantém o sistema funcional e ainda permite ver o que estava sendo bloqueado.
ℹ️ Se precisar mudar o modo: a ferramenta oficial é o setenforce. Rodar sudo setenforce 0 coloca em permissive até o próximo boot. Para tornar permanente, edite /etc/selinux/config (não fazemos isso automaticamente — é uma decisão sua).
